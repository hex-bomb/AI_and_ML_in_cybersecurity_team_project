# Эксплуатация

Установка передаётся заказчику целиком: docker-compose, `.env` и команды ниже.
Всё остальное — проверки, которые можно запустить до того, как что-то сломалось.

## `make doctor`

Проверяет установку и ничего не меняет:

| Что               | Как проверяется                                      |
| ----------------- | ---------------------------------------------------- |
| Конфигурация      | `.env` на месте, обязательные секреты заданы          |
| Генерация         | `LLM_BASE_URL`; пустой — предупреждение, а не отказ   |
| Контейнеры        | все сервисы запущены, нет `unhealthy`                |
| PostgreSQL        | отвечает, три базы на месте, миграции применены      |
| Очередь событий   | `outbox_events` пуст                                 |
| Оригиналы         | `/data/blobs` доступен на запись                     |
| Elasticsearch     | кластер не `red`, индекс не пуст                     |
| Kafka             | топик `documents` есть, у группы `ingest` нулевой лаг |
| Модели            | `embedding` отдаёт векторы размерности 384           |
| Сервисы           | `answer` и `retrieval` отвечают на `/healthz`        |

Код возврата `1` — есть проблема уровня `FAIL`: установка не готова принимать
вопросы. `warn` — повод посмотреть, но сервис работает.

```bash
make doctor
```

## Резервная копия

```bash
make backup                       # backups/<дата-время>
make backup DIR=backups/nightly   # свой каталог
```

Копия состоит из трёх дампов PostgreSQL (`pg_dump --format=custom`) и архива
тома с оригиналами. Рядом кладутся `manifest.txt` (время, коммит, образы) и
`SHA256SUMS`.

**Копия без оригиналов неполная.** В базе только метаданные и `storage_key`:
сам файл лежит в томе `docs-blobs`, поэтому `backup.sh` снимает и его.

Elasticsearch в копию не входит: индекс производный, его пересобирают.

## Восстановление

```bash
make restore DIR=backups/nightly
RESTORE_CONFIRM=yes make restore DIR=backups/nightly   # без вопроса
```

Порядок: сверка контрольных сумм → остановка `answer`, `documents`,
`retrieval`, `ingest`, `router` → пересоздание баз → `pg_restore` → замена
оригиналов → запуск → пересборка индекса.

Индекс пересобирается обязательно: если база откатилась назад, а Elasticsearch
остался прежним, поиск покажет документы, которых в базе уже нет, и не покажет
восстановленные.

После восстановления выполните `make doctor`: он проверит, что все версии
проиндексированы.

## Пересборка индекса

```bash
make reindex
```

`documents` ставит в очередь все опубликованные версии, `ingest` перечитывает
текст и пересчитывает векторы. Скрипт ждёт, пока в индексе окажется столько же
опубликованных документов, сколько в базе, и только потом выходит с нулём:
пустой outbox значит «отправлено», а не «проиндексировано».

Нужна после восстановления, смены модели эмбеддингов или ручной чистки
Elasticsearch.

## Сроки хранения

```bash
make retention                        # только производные данные
CONVERSATION_DAYS=180 make retention  # плюс история диалогов
```

Удаляется:

- отправленные события `outbox_events` старше `OUTBOX_DAYS` (по умолчанию 7);
- просроченные записи идемпотентности в `vektor_docs` и `vektor_answer`;
- при `CONVERSATION_DAYS > 0` — диалоги старше срока вместе с репликами и
  цитатами, а также `product_events` за тот же период.

Что **не** удаляется автоматически:

- оригиналы и старые версии документов — удаление файла и строки версии должно
  идти вместе, и фоном без явной политики это однажды снимет нужный документ;
- `audit_events` — журнал неизменяем, чистить его можно только осознанно и
  вручную.

## Сценарии отказа

| Что случилось                           | Что делать                                                          |
| --------------------------------------- | ------------------------------------------------------------------- |
| `answer` отвечает `503 LLM_UNAVAILABLE` | проверить `LLM_BASE_URL`, ключ и сеть до провайдера; поиск работает |
| документ не находится                   | `make doctor`, затем `make reindex`                                 |
| восстановили копию, поиск пуст          | `make reindex`                                                      |
| индекс пуст после `make up`             | `python3 infra/scripts/seed-corpus.py` — корпус демо                |
| `ingest` отстаёт                        | `docker compose logs ingest`; лаг виден в `make doctor`             |
| контейнер `unhealthy`                   | `docker compose logs <сервис>`; `answer` без базы не стартует       |

## Обновление установки

1. `make backup`.
2. Заменить образы на новые версии (они зафиксированы тегами в compose).
3. `make up` — миграции `documents` и `auth` применяет Flyway, `answer` —
   собственный прогон миграций при старте.
4. `make doctor`, затем `make reindex`, если менялась модель эмбеддингов.
5. Если что-то пошло не так: старые образы + `make restore DIR=...`.
