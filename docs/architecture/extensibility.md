# Как расширять «Вектор»

Эта страница для тех, кто добавляет в систему что-то новое: эндпоинт,
провайдера LLM, формат файла, событие, сервис или фичу виджета. Она отвечает на
два вопроса: куда положить код и что проверить перед PR.

Сейчас типовое изменение часто требует правок в нескольких местах сразу, и
каждая такая правка — шанс, что одно место обновят, а другое забудут. Правила
ниже уменьшают число таких мест. Где договорённость ещё не внедрена, это
написано прямо.

## Принципы

1. Контракт важнее прозы. Всё, что пересекает границу процесса (HTTP, Kafka,
   claims в токене, коды ошибок, `postMessage`), описывается в `contracts/` и
   проверяется машиной. Комментарии и эта страница только объясняют решения.

2. Зависимости идут внутрь. Транспорт знает про сценарии, сценарии про домен,
   домен не знает ни про кого. Клиенты к внешнему миру подключаются снаружи.

3. Расширение — это новый файл. Если для фичи нужно править «центральный» класс,
   точку расширения выбрали неверно. Признаки: `switch` по типу в двух местах,
   класс `Clients`, который знает про всех соседей, общий стор на всё приложение.

4. Абстракция появляется на шве. Шов — это внешний ввод-вывод, граница между
   сервисами или место, где вторая реализация уже есть (или точно будет: фейк в
   тестах считается). Остальное — обычный код без интерфейсов «на будущее».

5. Требование без автоматической проверки держится на честном слове. Поэтому у
   каждого правила ниже есть либо проверка в CI, либо пометка «пока вручную».

6. Отказ соседа — штатный режим. Сервис должен отвечать осмысленно, когда
   зависимость недоступна. Образец — `HybridSearch`: без эмбеддингов поиск
   продолжает работать на лексике и пишет об этом в лог.

## Карта связей

```
widget ──► router ──► answer ──► retrieval ──► Elasticsearch
                         │            └──► embedding
                         ├──► documents (extract)
                         └──► LLM

documents ──Kafka──► ingest ──► embedding, Elasticsearch
auth ──JWKS──► documents, retrieval, answer (ключи кэшируются, вызова на каждый запрос нет)
```

Синхронные вызовы идут только вниз по этой схеме. Обратная стрелка — повод для
ADR и, скорее всего, для события вместо вызова.

Данными владеет один сервис. У каждого своя БД в `infra/postgres/init.sql`, и в
чужую базу не ходит никто: данные отдаются через API или событие.

Новый сервис оправдан, если выполнено хотя бы два условия: другая ось
масштабирования, другой владелец данных, другая экосистема библиотек, отдельный
цикл релизов. «Красивее по слоям» — не причина.

## Одна форма для всех сервисов

Языки разные, слои одинаковые. Это позволяет открыть незнакомый сервис и за
минуту понять, где искать вход, где правила и где инфраструктура.

```
transport    принять запрос, проверить форму, вызвать сценарий, вернуть ответ
application  сценарии: один сценарий — один файл
domain       типы и правила без ввода-вывода
ports        что сценарию нужно от внешнего мира
adapters     HTTP-клиенты, JDBC, Kafka, Elasticsearch, LLM
```

Стрелки зависимостей направлены к домену и портам. Адаптеры и транспорт знают о
них, обратного знания нет.

| Понятие   | Python                 | Java                     | Go                        |
| --------- | ---------------------- | ------------------------ | ------------------------- |
| Сценарий  | `usecases/ask.py`      | `app/AskQuestion.java`   | `internal/ask/ask.go`     |
| Порт      | `ports.py`, `Protocol` | `port/Completer.java`    | интерфейс у потребителя   |
| Адаптер   | `clients.py`           | `adapter/JdbcStore.java` | `internal/search/es.go`   |
| Транспорт | `api/answers.py`       | `web/Api.java`           | `internal/api/handler.go` |
| Настройки | `settings.py`          | `@Value` / `Settings`    | `config.go`               |
| Фейк      | `tests/fakes.py`       | `src/test/.../Fakes`     | `fake_test.go`            |

Три правила формы:

1. Транспорт тонкий — 10–20 строк на эндпоинт: разобрать вход, вызвать сценарий,
   перевести ошибку в ответ.
2. Сценарий бросает доменную ошибку с кодом из общего словаря, а не возвращает
   HTTP-статус. Конверт собирает один обработчик на сервис.
3. Настройки читаются один раз на старте, проверяются сразу и передаются явно.
   `os.environ` в глубине кода — признак, что composition root размазан.

## Платформенный минимум

Без этого сервис не считается готовым, на каком бы языке он ни был написан.

| Свойство       | Требование                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------- |
| `X-Request-ID` | принять входящий (до 128 символов) или создать; вернуть в заголовке и в теле ошибки; передать дальше |
| Конверт ошибки | `{"error":{"code","message","details"?},"request_id"}`                                               |
| `/healthz`     | `200`, без обращения к зависимостям                                                                  |
| `/metrics`     | `http_requests_total{method,path,status}`, `http_request_duration_seconds{path}`                     |
| Метка `path`   | шаблон маршрута, а не сырой URI: иначе кардинальность взрывается                                     |
| Таймауты       | на каждый исходящий вызов, значения из настроек                                                      |
| Завершение     | корректная обработка SIGTERM (Spring `shutdown: graceful`, `srv.Shutdown`)                           |
| Логи           | JSON, с `request_id`                                                                                 |

Имена метрик во всех трёх языках уже совпадают: Micrometer приводит
`http.requests` к `http_requests_total`, обработчики в Go и Python пишут те же
имена. Следите только за меткой `path`.

## Python: `answer`, `embedding`, `ingest`

`answer` уже приведён к этой раскладке (PR #8): бизнес-логика живёт в
сценариях, роуты только разбирают вход.

```
answer/app/
  main.py          сборка: роуты, middleware, обработчики ошибок
  deps.py          authenticated + сборка сценариев над адаптерами
  errors.py        AppError с кодами; нейтральные Unavailable/BadRequest
  ports.py         Retriever, Completer, Embedder, TextExtractor
  settings.py      TOP_K, MAX_UPLOAD и прочие значения из окружения
  usecases/        ask.py, ask_file.py, common.py
  rag.py           чистое ядро: промпт, разбор ответа, цитаты, нарезка
  guard.py         политика: инъекции в промпт и платёжные данные
  clients.py       адаптеры соседей (JWKS, retrieval, embedding, documents, LLM)
```

Сценарий выглядит так:

```python
class AskQuestion:
    def __init__(self, retriever: Retriever, completer: Completer, top_k: int = 4) -> None:
        self._retriever, self._completer, self._top_k = retriever, completer, top_k

    async def __call__(self, question: Question) -> dict:
        reason = blocked_reason(question.text)
        if reason:
            raise AppError.forbidden("Запрос отклонён политикой безопасности", {"reason": reason})
        hits = await self._retriever.search(question.text, self._top_k, question.token)
        if not hits:
            return {"status": "no_evidence", "answer": NO_EVIDENCE, "citations": []}
        return await answer_from_hits(self._completer, question.text, question.history, hits)
```

Тест такого сценария не поднимает HTTP и не трогает `httpx`: адаптеры подменяются
фейками из `tests/fakes.py`.

Что осталось сделать в Python:

- разрезать `clients.py` на адаптеры по одному за PR и завести реестр провайдеров
  LLM (`@provider("gigachat")`), чтобы новый провайдер был отдельным файлом;
- сделать `guard.py` набором объектов-политик, чтобы набор включался профилем
  клиента, а не правкой модуля;
- вынести общие для трёх сервисов вещи (middleware, конверт, настройки) в пакет
  `vektor_platform` — но только когда дублей станет три, а не заранее.

## Java: `auth`, `documents`

Сейчас в `documents` один контроллер `Api` на публичные и внутренние эндпоинты,
бизнес-правила и валидация — прямо в нём. Это работает, но каждый новый эндпоинт
удлиняет класс и требует не забыть проверку `X-Internal-Token`.

Целевая раскладка — пакеты по фичам, внутри слои:

```
ru.vektor.docs
  web/        Api (публичный), InternalApi, dto/
  app/        UploadDocument, IngestDocument, ListDocuments
  domain/     Audience, DocumentVersion
  port/       DocumentStore, DocumentEvents, TextExtractor
  adapter/    JdbcDocumentStore, KafkaDocumentEvents, extract/
  platform/   TokenVerifier, RequestIdFilter, ApiErrors
```

Отдельный внутренний контроллер позволяет повесить `X-Internal-Token` на путь
`/internal/**` одним фильтром; тогда забыть проверку на новом эндпоинте не
получится.

Аудитории (`public`, `employee`) сейчас заданы в трёх местах: `switch` в `auth`,
ограничение в схеме БД, фильтр в запросе к Elasticsearch. Пока их две, это
терпимо. Третья аудитория должна добавляться строкой в словарь, а не поиском по
коду.

Проверка внутреннего токена сравнивает байты за постоянное время
(`MessageDigest.isEqual`), а пустое значение настройки запрещает все внутренние
вызовы. Это поведение не меняйте.

Расширение форматов файлов делается добавлением компонента:

```java
public interface TextExtractor {
    boolean supports(String extension);
    String extract(byte[] content) throws Exception;
}
```

`Extract` собирает все реализации через конструктор и выбирает подходящую. Пока
форматов три, `switch` по расширению тоже нормален; список стратегий стоит
вводить на четвёртом.

## Go: `retrieval`

Сервис уже устроен так, как надо: `cmd/retrieval` только собирает зависимости,
`internal/api` — транспорт, `internal/search` — Elasticsearch, эмбеддинги и RRF,
`internal/jwks` — проверка токена. Держите это устройство.

Правила, которые стоит сохранять:

- интерфейс объявляет потребитель и только с нужными ему методами
  (`SearchService` в `api` — образец);
- `context.Context` первым аргументом, таймаут ставит транспорт;
- ошибки оборачиваются с `%w` и различаются через `errors.Is`/`As`;
- только стандартная библиотека: сервис собирается без сети;
- табличные тесты и `httptest` вместо моков.

Новая стадия выдачи (реранкер, фильтр по свежести) добавляется как отдельный тип
и подключается в `main.go`. Делать это заранее не нужно: пока стадий нет, список
опций — лишний код.

```go
type Stage interface {
    Apply(ctx context.Context, query string, hits []search.Hit) ([]search.Hit, error)
}
```

Ошибка стадии — деградация: залогировать переход и вернуть выдачу без неё, а не
отказывать пользователю.

## React: `widget`

В виджете уже есть слои Feature-Sliced: `shared`, `entities`, `widgets`, `pages`.
Не хватает слоя `features`, а `entities/chat/model/chatStore.ts` держит слишком
много: конфиг, сессию, вложения, черновик, чаты, тексты ошибок.

| Что сейчас в `chatStore.ts` | Куда                                |
| --------------------------- | ----------------------------------- |
| конфиг и сессия             | `shared/config`, `entities/session` |
| чаты и сообщения            | `entities/chat/model`               |
| отправка, ответ, история    | `features/send-message/model`       |
| вложения и черновик         | `features/attach-file/model`        |
| тексты ошибок по кодам      | `shared/lib/errors`                 |

Связывать срезы лучше событиями effector (`sample`), а не импортом внутренностей
соседа. Тогда новая фича — это новая папка и `index.ts`, а не правка общего стора.

Протокол `postMessage` стоит описать типами с версией: сейчас и загрузчик, и
виджет знают его по памяти.

```ts
export type HostToWidget =
  | { source: "aks-host"; v: 1; type: "config"; payload: HostConfig }
  | { source: "aks-host"; v: 1; type: "open" | "close" | "toggle" };
```

Виджет отправляет сообщения хосту с `targetOrigin = "*"`. Для установки на разные
сайты понадобится брать origin из настроек загрузчика (или профиля клиента) и
проверять версию протокола.

## Рецепты

### Новый эндпоинт

1. Опишите путь и схемы в `contracts/openapi/openapi.yaml`, добавьте запрос в
   Postman, строку в `docs/reference/api.md`. Если путь новый по префиксу —
   маршрут в `infra/nginx/router.conf`.
2. Напишите сценарий и порт, который ему нужен; фейк для теста.
3. Тест сценария (красный) → реализация → тест зелёный.
4. Тонкий роут. Ошибки — через общий механизм, не через `return JSONResponse`.
5. `make test` и запрос из Postman.

### Новый провайдер LLM

1. Отдельный адаптер с реализацией `Completer`; для реестра — декоратор
   `@provider("имя")`, когда реестр появится.
2. Тест через `httpx.MockTransport`: успех, 401 с повторным обменом токена,
   5xx → `Unavailable`.
3. Настройки — в `Settings` с значениями по умолчанию, `.env.example` и
   `docker-compose.yml`.
4. Раздел в `docs/environments/local-development.md`.

Пока реестра нет, добавление ветки в `Clients` допустимо один раз. Второй
провайдер — уже повод для реестра.

### Новый формат файла

1. Компонент `TextExtractor` и тест на маленьком файле в `src/test/resources`.
2. Расширение — в сообщение об ошибке, в описание эндпоинта в OpenAPI и в
   `docs/services/documents.md`.
3. Защита от архивных бомб и лимит страниц — внутри адаптера.

### Новое поле или версия Kafka-события

1. Схема в `contracts/events/` (папка появится по шагу 2 плана), описание в
   `docs/infrastructure/kafka.md`.
2. Новые поля — необязательные. Удаление или смена смысла — только новый тип
   `...v2`, оба живут до миграции потребителей.
3. Продюсер публикует через порт, а не напрямую из сценария: тогда переход на
   outbox меняет один адаптер.
4. Потребитель идемпотентен и не падает на незнакомой версии события.

Outbox и DLQ появятся, когда будет первый реальный клиент или первое потерянное
событие. Тогда: таблица `outbox`, ретранслятор с `FOR UPDATE SKIP LOCKED`, топик
`*.dlq` и метрика его размера.

### Новый микросервис

1. Проверьте критерии из раздела «Карта связей».
2. Каркас: `/healthz`, `/metrics`, `X-Request-ID`, конверт ошибки, Dockerfile,
   healthcheck, один тест сценария.
3. `docker-compose.yml`: `build`, `environment`, `depends_on` с
   `condition: service_healthy`, порт на `127.0.0.1`.
4. `infra/prometheus/prometheus.yml`, панель в Grafana, своя БД в
   `infra/postgres/init.sql`, если сервис владеет данными.
5. `router.conf` — только публичные пути; `/internal/*` не маршрутизируются.
6. `docs/services/<имя>.md` и строка в `README.md`.

### Новый канал или группа

1. Словарь каналов (`public`, `internal`) и групп — в `auth`.
2. Миграция с расширением `CHECK` в `access_grants`.
3. Новая роль или группа в `scopes()`/`grp` в `auth`, каналы в `Claims.Channels()`
   и фильтр в запросе к Elasticsearch.
4. Тест: токен с новой группой видит документы этой группы и не видит чужие.

## Автоматические проверки

| Правило                                | Инструмент                         | Статус       |
| -------------------------------------- | ---------------------------------- | ------------ |
| OpenAPI ↔ Postman ↔ маршруты router    | `scripts/check-contracts.py`       | есть         |
| Слои Python                            | `import-linter`                    | предлагается |
| Слои Java                              | ArchUnit в `mvn test`              | предлагается |
| Слои виджета                           | `steiger` или `dependency-cruiser` | предлагается |
| Форматирование и линт Python           | `ruff`                             | есть         |
| Форматирование Go, `vet`, `-race`      | `gofmt`, `go vet`, `go test -race` | есть         |
| Тесты Java                             | `mvn test` в CI                    | есть         |
| Секреты и опасные вызовы               | `semgrep`                          | есть         |
| Одинаковое поведение JWT в трёх языках | conformance-векторы в `contracts/` | предлагается |

`scripts/check-contracts.py` падает, если маршрут в `router.conf` или запрос в
Postman перестал совпадать с OpenAPI.

## Перед PR

- Контракт обновлён: OpenAPI, Postman, `docs/reference/api.md`, при необходимости
  `router.conf`.
- Новая логика — в сценарии или домене, не в обработчике и не в адаптере.
- Ошибки — доменные, коды из общего словаря.
- Новая настройка: значение по умолчанию, `.env.example`, `docker-compose.yml`,
  раздел в документации.
- Есть тест сценария без сети. Для транспорта достаточно одного теста на эндпоинт.
- Метрики и `request_id` появляются и на ошибке.
- Поведение при недоступной зависимости описано и покрыто тестом.
- `make test` и `make lint` зелёные.
- Коммит в формате `<область>: <что изменилось>`.

## Чего не делать

- Не добавлять абстракцию без второго потребителя. Фейк в тестах считается
  потребителем, «возможно, завтра понадобится» — нет.
- Не делать общую библиотеку между разными языками. Одинаковое поведение
  проверяется векторами и тестами, а не общим рантаймом.
- Не заводить `utils`, `helpers`, `common`, `manager` как свалку.
- Не добавлять `if tenant == ...` в код. Различия клиентов — это данные профиля.
- Не ходить в базу соседнего сервиса.
- Не логировать полные запросы, токены и документы «для отладки».
- Не превращать рефакторинг в фичу: отдельные PR читаются за 15 минут, общий —
  нет.
