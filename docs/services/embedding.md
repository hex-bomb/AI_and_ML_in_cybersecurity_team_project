# embedding

Модель E5 по HTTP: кодирование текста в векторы для поиска. Батчинг, прогрев,
корректная деградация без весов модели.

## Ответственность

- `POST /embed` — кодирование списка текстов.
- `GET /healthz` — состояние модели (`ok` / `degraded`).
- `/metrics`.

Не индексирует и не ищет: только превращает текст в вектор.

## Контракт

Запрос: `{"texts": ["...", ...], "kind": "query" | "passage"}` (до 256 текстов).
Ответ: `{"vectors": [[...], ...]}`; при деградации — `{"vectors": [null, ...],
"degraded": true, "reason": "..."}`.

Префиксы `query: ` / `passage: ` добавляются автоматически — E5 требует их для
разделения ролей текста. Векторы нормализованы (косинуса достаточно для сравнения).

## Поведение

- Модель загружается один раз при первом обращении, повторных попыток не делает.
- Кодирование идёт под семафором (`CONCURRENCY`), вычисление — в отдельном потоке,
  чтобы не блокировать event loop.
- Текст без токенов даёт `null`-вектор, а не ошибку.

## Деградация

Если весов модели нет (`MODEL_PATH`/`TOKENIZER_PATH`) или ONNX не запустился,
сервис остаётся работать: `/embed` возвращает `null`-векторы с `degraded: true`,
`/healthz` — `degraded` с причиной. Потребители (retrieval, answer) на `null`
переходят на лексику или первые `top_k`.

## Конфигурация

| Переменная       | По умолчанию     | Назначение               |
| ---------------- | ---------------- | ------------------------ |
| `MODEL_PATH`     | `model.onnx`     | Веса ONNX                |
| `TOKENIZER_PATH` | `tokenizer.json` | Токенизатор              |
| `BATCH_SIZE`     | `8`              | Размер пакета            |
| `CONCURRENCY`    | `2`              | Параллельных кодирований |
| `THREADS`        | `2`              | Потоки intra-op ONNX     |
| `MAX_TOKENS`     | `512`            | Обрезка токенов          |

Веса модели в Git не попадают (`.gitignore`: `apps/backend/embedding/models/`).

## Тесты

Юнит-тестов нет: логика — обёртка над ONNX, проверяется интеграционно на стенде.
