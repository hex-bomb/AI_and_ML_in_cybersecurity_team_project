# retrieval

Гибридный поиск по базе знаний: лексический BM25 + kNN по эмбеддингам, слияние
RRF. Кодировать запрос и искать — единственная его работа.

## Ответственность

- `POST /api/v1/search` — выдача фрагментов по запросу.
- `GET /healthz`, `/metrics`.

Не хранит состояние, не пишет в индекс (только читает Elasticsearch).

## Архитектура

```
cmd/retrieval        — композиция: конфиг, клиенты, сервер, graceful shutdown
internal/api         — HTTP-слой, авторизация, метрики, оркестрация поиска
internal/jwks        — проверка RS256-JWT по JWKS auth
internal/search      — ядро: тела запросов ES, слияние RRF, отображение в Hit
```

Границы намеренные: `search` не знает про HTTP и JWT, `api` не знает про формат
запросов ES. Ядро (`RRF`, `LexicalBody`, `KnnBody`, `ToHit`) — чистые функции и
покрыто тестами.

## Контракт

Запрос: `{"kb_id", "query", "top_k"}` (`top_k` 1..10, по умолчанию 5).
Ответ: `{"status": "ok"|"no_results", "hits": [...], "request_id"}`.

Поле доступа: `kb_id` должен совпадать с `kb` из токена — чужая база
неотличима от несуществующей (`404 KB_NOT_FOUND`). Фильтр по аудиториям
(`scp`) уходит внутрь запроса к ES, наружу чужие документы не попадают.

## Как считается

1. Запрос кодируется сервисом `embedding`. Если тот недоступен — работает
   только лексика (это деградация, а не отказ, ошибка логируется).
2. Параллельно идут lexical и kNN запросы к Elasticsearch.
3. Результаты сливаются `RRF` (`k=60`), tie-break — по порядку первого появления.
4. Ошибка обеих систем → `503 SEARCH_UNAVAILABLE`. Ошибка одной — деградация.

Таймаут поиска — 15 с, HTTP-клиент к зависимостям — 20 с.

## Безопасность

JWT проверяется по JWKS (алгоритм строго `RS256`, проверка `exp`). Мьютекс
кэша ключей не удерживается на время сетевого вызова: обновление идёт под
отдельным лочом, при живых старых ключах сбой обновления — warning, а не отказ.

| `ES_URL`        | `http://localhost:9200`                       |

| `ADDR`          | `:8080`                                       |

## Наблюдаемость

Самописный Prometheus-экспортер в `/metrics`: `http_requests_total`,
`http_request_duration_seconds`. Метрики вешаются только на `/api/v1/search`,
кардинальность ограничена по построению.

## Тесты

`go test ./...` — ядро (`search`) и верификатор (`jwks`) покрыты тестами, включая
отклонение просроченных токенов и неизвестного `kid`. Тесты не открывают сокеты:
JWKS-сервер подменён через `RoundTripper`. В CI дополнительно `go test -race`.
