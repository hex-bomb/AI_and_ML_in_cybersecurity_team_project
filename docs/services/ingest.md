# ingest

Конвейер индексации: событие из Kafka → текст из `documents` → фрагменты →
эмбеддинги → индекс Elasticsearch. Работает фоном, HTTP нужен только для
наблюдаемости.

## Ответственность

- `GET /healthz` — состояние конвейера (не просто процесса).
- `/metrics`.

Читает топик `kb.document.upserted`, пишет в индекс `vektor-chunks`. Не принимает
HTTP-запросов на запись — вход только через Kafka.

## Контракт

Событие (см. `docs/services/documents.md`): `document_id`, `version_id`, `kb_id`,
`audience`, `title`.

Порядок при обработке:

1. Текст версии — `GET /internal/documents/.../text` c `X-Internal-Token`.
2. Нарезка на окна по предложениям (`CHUNK_CHARS` с перекрытием `CHUNK_OVERLAP`).
3. Эмбеддинги — `POST /embed`.
4. Bulk-запись новых фрагментов, **затем** удаление старых (`_delete_by_query`) —
   окна «документа нет» не возникает.

`chunk_id` — детерминированный SHA-256 от документа, версии, позиции и текста,
поэтому повторная индексация идемпотентна и не плодит дубликаты.

## Доставка и ретраи

Консьюмер с `enable_auto_commit=false`: commit выполняется только после успеха
или исчерпания попыток. Транзиентный сбой (`documents`, `embedding`, ES) ретраится
`INGEST_MAX_ATTEMPTS` раз с экспоненциальной задержкой от
`INGEST_RETRY_BASE_SECONDS`. Это закрывает риск молчаливого выпадения документа
из базы при однократном отказе.

Пока ретраи не исчерпаны, сообщение не сдаётся — документ остаётся в очереди.
После исчерпания сообщение считается безнадёжным, ошибка логируется, конвейер
продолжает работу (одно плохое сообщение не останавливает поток).

## Здоровье конвейера

`/healthz` отвечает `503 degraded`, если фоновая задача умерла (Kafka/ES
недоступны при старте) или ещё не запущена. Без этого процесс выглядел бы живым,
а индексация — мёртвой: контейнер оставался бы в репликах и не принимал бы
трафик.

## Конфигурация

| Переменная                      | По умолчанию                              | Назначение                           |
| ------------------------------- | ----------------------------------------- | ------------------------------------ |
| `KAFKA_BOOTSTRAP`               | `localhost:9092`                          | Брокер                               |
| `KAFKA_TOPIC`                   | `kb.document.upserted`                    | Топик                                |
| `KAFKA_GROUP`                   | `ingest`                                  | Группа консьюмеров                   |
| `ES_URL` / `ES_INDEX`           | `http://localhost:9200` / `vektor-chunks` | Индекс                               |
| `DOCUMENTS_URL`                 | `http://localhost:8080`                   | Источник текстов                     |
| `DOCUMENTS_INTERNAL_TOKEN`      | —                                         | Секрет `/internal/*`; пусто = отказ  |
| `EMBEDDING_URL`                 | `http://localhost:8000`                   | Сервис эмбеддингов                   |
| `CHUNK_CHARS` / `CHUNK_OVERLAP` | `1200` / `200`                            | Нарезка, символы                     |
| `EMBEDDING_DIMS`                | `384`                                     | Размерность вектора                  |
| `INGEST_MAX_ATTEMPTS`           | `3`                                       | Попыток на сообщение                 |
| `INGEST_RETRY_BASE_SECONDS`     | `2`                                       | База задержки ретраев                |
| `ES_REFRESH`                    | `false`                                   | `refresh` в bulk/delete (для стенда) |

Индекс создаётся автоматически при старте, если его нет (mapping с
`dense_vector` на `EMBEDDING_DIMS`, русский анализатор для `title`/`text`).

## Наблюдаемость

`ingest_documents_total{status}` (`ok`/`error`), `ingest_chunks_total`.
Логи: успешная индексация — `info`, ретраи — `warning`, выпавшее сообщение — `error`.

## Тесты

`python -m pytest apps/backend/ingest/tests` — ядро (`chunk_id`, сборка bulk,
запрос удаления старых фрагментов). В CI гоняется отдельной пачкой.
