# ВЕКТОР

Чат по базе знаний с ролями, гибридным поиском и записью через диалог.
Микросервисы на Go, Java и Python; локальная развёртка — docker-compose и `.env`.

## Структура

| Каталог          | Что внутри                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| `apps/backend/`  | Сервисы: `auth`, `documents` (Java), `retrieval` (Go), `answer`, `embedding`, `ingest` (Python) |
| `apps/frontend/` | `web-app` (лендинг) и `widget` (встраиваемый виджет), npm workspaces                            |
| `contracts/`     | OpenAPI и коллекция Postman                                                                     |
| `infra/`         | Конфиги (router, Prometheus, Grafana, Postgres), скрипты и демо-корпус                          |
| `docs/`          | Документация (MkDocs Material)                                                                  |
| `scripts/`       | `test.sh`, `lint.sh`, `check-contracts.py`                                                      |

## Запуск

```sh
make up      # .env, сборка образов, контейнеры, корпус, smoke
make down    # остановить (тома сохраняются)
make clean   # остановить и удалить тома (.env сохраняется)
make test    # ruff, pytest, контракты, go build/vet
make lint    # проверки без тестов
```

После `make up`:

| Что                                       | Где                                                      |
| ----------------------------------------- | -------------------------------------------------------- |
| Лендинг и виджет                          | <http://localhost:8080>                                  |
| Grafana (дашборд «Vektor»)                | <http://localhost:3000>                                  |
| Prometheus                                | <http://localhost:9090>                                  |
| Swagger `auth` / `documents`              | `localhost:8081` / `localhost:8082` → `/swagger-ui.html` |
| FastAPI `answer` / `embedding` / `ingest` | `localhost:8083`–`8085` → `/docs`                        |

Подробности, включая разбор сбоев, — в
[документации](docs/index.md).

### Генерация ответов (LLM)

`/answers` без LLM отвечает `503 LLM_UNAVAILABLE` — поиск и документы при этом
работают. Ключ и настройки лежат в `.env` (см. `.env.example`); для GigaChat
прокси не нужен, `answer` сам обменивает Authorization key на 30-минутный
токен:

```sh
# вписать в .env, затем пересоздать контейнер:
LLM_PROVIDER=gigachat
LLM_API_KEY=<authorization key с developers.sber.ru>
docker compose up -d answer
```

Адрес (`https://api.giga.chat/v1`) и модель (`GigaChat-2`) подставляются
автоматически. Полный разбор, ollama и любой OpenAI-совместимый эндпоинт — в
[локальной развёртке](docs/environments/local-development.md#генерация-ответов-llm).

## Пользователи

Вход — в шапке лендинга справа. Сессия — JWT в httpOnly-cookie.

| Логин      | Пароль                        | Роль      | Что видит              |
| ---------- | ----------------------------- | --------- | ---------------------- |
| `user`     | `user`                        | клиент    | публичные документы    |
| `employee` | `employee`                    | сотрудник | публичные и внутренние |
| `admin`    | см. `AUTH_DEV_ADMIN_PASSWORD` | сервисный | публичные и внутренние |

Аккаунты создаются только с профилем `dev` (задан в `docker-compose.yml`).
Токен `admin` живёт практически без срока (`AUTH_ADMIN_SESSION_TTL`, по умолчанию
~100 лет) — исключение для сервисных вызовов на стенде, в проде сиды выключены.

## Как это работает

- **Поиск:** BM25 с русским анализатором + kNN по эмбеддингам, слияние RRF;
  фильтр по базе и аудитории уходит внутрь запроса к Elasticsearch.
- **Ответ:** фрагменты нумеруются и уходят в LLM; модель возвращает JSON с номерами
  источников, номера зажимаются по выданному набору.
- **Права:** роль превращается в `scp` при выпуске токена, потребители фильтруют
  по `scp`, а не по роли.
- **Загрузка:** сотрудник кладёт `.md/.txt/.pdf/.docx`; разбор идёт в Java,
  индексация — асинхронно через Kafka, запрос не ждёт эмбеддингов.
- **Файл к вопросу:** файл разбирается внутри запроса, в базу не попадает.
- **Классификатор:** лексические правила (инъекция в промпт, платёжные данные) —
  могут только запретить.
- **Внутренний контур:** `/internal/*` в `documents` не маршрутизируются
  входным router и закрыты общим токеном (`X-Internal-Token`).

## CI

На каждый push/PR: ruff + pytest (answer, ingest), `go test -race`, `mvn test`,
lint/typecheck фронтенда, mkdocs `--strict`, semgrep, `docker compose config/build`.
Хуки `pre-commit` локальные и не дублируются в CI — их проверки уже покрыты
job'ами выше.

## Ограничения стенда

- Один узел Elasticsearch; индекс производный, восстанавливается повторной
  публикацией документов.
- Нет TLS, cookie без `Secure` — стенд локальный.
- Нет DLQ и outbox: индексация чинится повторной публикацией.
- Удаления документов через API нет.
- JWT живёт 8 часов (кроме `admin`); выход удаляет cookie, но токен доживает срок.
